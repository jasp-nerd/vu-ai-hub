📐 Graph Theory Fundamentals

Basic Definitions

A graph G = (V, E) consists of:

  • V: A finite set of vertices (nodes)
  • E: A finite set of edges

Key Terminology

  • Order: |V| (number of vertices)
  • Size: |E| (number of edges)
  • Adjacent vertices: Two vertices u and v where (u,v) ∈ E
  • Neighborhood N(v): Set of vertices adjacent to v
  • Degree deg(v): Number of edges incident to v

Example Graph Visualization

V = {A, B, C, D, E}, |V| = 5, |E| = 7

Trees

A tree is a connected graph with no cycles.

Fundamental Tree Properties

  • A tree with n vertices has exactly n-1 edges
  • Every tree with n ≥ 2 has at least 2 leaves (vertices of degree 1)
  • Between any two vertices, there is exactly one path

Tree with 7 vertices and 6 edges (leaves shown in gray)

🎯 Handshaking Lemma (First Theorem in Graph Theory)

Handshaking Lemma

Σv∈V deg(v) = 2|E|

The sum of all vertex degrees equals twice the number of edges.

Corollary: The number of vertices with odd degree is always even.

Proof Sketch

When counting degrees, each edge contributes exactly 2 to the sum (once for each endpoint). Therefore Σ deg(v) = 2|E|.

Since 2|E| is even, there must be an even number of vertices with odd degree.

Example

In a graph with 5 vertices and degree sequence (3, 3, 2, 2, 2):

Sum = 3 + 3 + 2 + 2 + 2 = 12 = 2 × 6, so |E| = 6 edges ✓

Walks, Paths, Trails, and Cycles

Critical Definitions

Term Definition Constraints
Walk Sequence v₁, v₂, ..., vₖ where vᵢvᵢ₊₁ ∈ E Vertices/edges can repeat
Trail Walk with distinct edges Vertices can repeat
Path Walk with distinct vertices No repeats! (implies distinct edges)
Cycle Path v₁, ..., vₖ plus edge vₖv₁ (k ≥ 3) Closed path
Circuit Trail that starts and ends at same vertex Closed trail

Hierarchy

Path ⊂ Trail ⊂ Walk

Every path is a trail, and every trail is a walk.

Distance, Eccentricity, Radius, Diameter

Distance Function d(u, v)

d(u, v) = length of shortest path from u to v (number of edges)

Properties (metric space):

  1. Non-negativity: d(u, v) ≥ 0, and d(u, v) = 0 ⟺ u = v
  2. Symmetry: d(u, v) = d(v, u)
  3. Triangle Inequality: d(u, v) ≤ d(u, w) + d(w, v) for all w

Advanced Distance Concepts

  • Eccentricity ecc(v): maxx∈V{d(v, x)} - farthest distance from v
  • Radius rad(G): minv∈V{ecc(v)} - smallest eccentricity
  • Diameter diam(G): maxv∈V{ecc(v)} - largest eccentricity
  • Center C(G): {v ∈ V | ecc(v) = rad(G)}
  • Periphery P(G): {v ∈ V | ecc(v) = diam(G)}

Bipartite Characterization Theorem

A graph with ≥ 2 vertices is bipartite if and only if it contains NO odd cycles.

This is a fundamental characterization! Can check bipartiteness by checking for odd cycles or using 2-coloring (BFS/DFS).

Graph Operations & Subgraphs

Deletion Operations

  • G - v: Remove vertex v and all edges incident to v
  • G - S: Remove vertex set S and all incident edges
  • G - e: Remove edge e (vertices remain)
  • G - T: Remove edge set T

Other Important Concepts

  • Connected: Path exists between every pair of vertices
  • Connected Component: Maximal connected subgraph
  • Complement Ḡ: Same V, edges are exactly those NOT in G
  • Subgraph H ⊆ G: V(H) ⊆ V(G), E(H) ⊆ E(G)
  • Induced Subgraph ⟨S⟩: Vertices S plus all edges between them from G

Graph Isomorphism

Isomorphic Graphs

Graphs G and H are isomorphic if there exists a bijection f: V(G) → V(H) preserving adjacency:

For all x, y ∈ V(G): xy ∈ E(G) ⟺ f(x)f(y) ∈ E(H)

Intuitively: Same structure, possibly different labels/drawings

🎯 Isomorphism Applications

  • Chemistry: Identifying molecular structures in databases
  • Social Networks: Detecting similar community patterns
  • Pattern Recognition: Finding structural similarities in images/data
  • Cryptography: Graph isomorphism problem for encryption schemes
  • Computational Complexity: GI is in NP, not known to be NP-complete!

Necessary Conditions for Isomorphism

If G ≅ H (G isomorphic to H), then:

  • |V(G)| = |V(H)|
  • |E(G)| = |E(H)|
  • Same degree sequence
  • Same number of connected components
  • Same diameter, same radius

Note: These are necessary but NOT sufficient conditions!

🔺 Lecture 5: Heaps & Heapsort

Heap Data Structure

A heap is a binary tree stored as an array, satisfying the heap property.

Max-Heap Property

For every node i (except root): A[PARENT(i)] ≥ A[i]

The largest element is stored at the root.

Array Index Navigation

PARENT(i) = ⌊i/2⌋
LEFT(i) = 2i
RIGHT(i) = 2i + 1

Max-Heap Visualization

Array: [16, 14, 10, 8, 7, 9, 3, 2, 4, 1]

Key Heap Operations

MAX-HEAPIFY(A, i) - O(log n)

Maintains the max-heap property by letting a violating element "float down"

MAX-HEAPIFY(A, i):
    l = LEFT(i)
    r = RIGHT(i)
    if l ≤ heap-size and A[l] > A[i]:
        largest = l
    else:
        largest = i
    if r ≤ heap-size and A[r] > A[largest]:
        largest = r
    if largest ≠ i:
        swap A[i] with A[largest]
        MAX-HEAPIFY(A, largest)

BUILD-MAX-HEAP(A) - O(n)

Builds a max-heap from an unordered array

BUILD-MAX-HEAP(A):
    heap-size = length(A)
    for i = ⌊length(A)/2⌋ downto 1:
        MAX-HEAPIFY(A, i)

HEAPSORT(A) - O(n log n)

HEAPSORT(A):
    BUILD-MAX-HEAP(A)
    for i = length(A) downto 2:
        swap A[1] with A[i]
        heap-size = heap-size - 1
        MAX-HEAPIFY(A, 1)

✓ Key Properties

  • Height of heap with n elements: ⌊log n⌋
  • Heapsort is in-place (sorts within the array)
  • Time complexity: O(n log n) worst-case
  • Not stable (doesn't preserve relative order of equal elements)

📊 Why BUILD-MAX-HEAP is O(n) Not O(n log n)

Surprising Result!

Naive analysis: n elements × O(log n) heapify = O(n log n)

Tighter analysis: Actually O(n)!

Detailed Complexity Analysis

Key insight: Most nodes are near the bottom of the heap!

  • At height h, there are at most ⌈n / 2h+1⌉ nodes
  • Cost to heapify a node at height h is O(h)
  • Total work: Σh=0 to ⌊log n⌋ ⌈n / 2h+1⌉ × O(h)
= O(n × Σh=0 to ∞ h/2h)
= O(n × 2)    // geometric series sums to 2
= O(n) ✓

Node Distribution by Height

Key Insight

Half the nodes are leaves (h=0, no work), quarter are at h=1 (constant work), etc. The expensive work at the root affects only 1 node!

Priority Queues

Heaps efficiently implement priority queues with these operations:

Priority Queue Operations

HEAP-MAXIMUM(A): return A[1]  // O(1)

HEAP-EXTRACT-MAX(A):  // O(log n)
    max = A[1]
    A[1] = A[heap-size]
    heap-size = heap-size - 1
    MAX-HEAPIFY(A, 1)
    return max

HEAP-INCREASE-KEY(A, i, key):  // O(log n)
    A[i] = key
    while i > 1 and A[PARENT(i)] < A[i]:
        swap A[i] with A[PARENT(i)]
        i = PARENT(i)

MAX-HEAP-INSERT(A, key):  // O(log n)
    heap-size = heap-size + 1
    A[heap-size] = -∞
    HEAP-INCREASE-KEY(A, heap-size, key)

📖 Priority Queue Applications (Book Ch. 6.5)

  • Job Scheduling: Max-priority queue keeps track of jobs to perform. Scheduler calls EXTRACT-MAX for highest-priority job, INSERT to add new jobs
  • Event-Driven Simulation: Min-priority queue with event occurrence times as keys. Simulator calls EXTRACT-MIN to choose next event, INSERT for future events
  • Prim's MST & Dijkstra: Use DECREASE-KEY operation (Chapters 21-22 in book)

🌳 Lecture 6 & 11: Binary Search Trees

Binary Search Tree Property

BST Property

For any node x:

  • All keys in left subtree ≤ x.key
  • All keys in right subtree ≥ x.key

Inorder traversal: 3, 6, 7, 13, 15, 17, 18, 18, 20 (sorted!)

BST Operations

TREE-SEARCH(x, k) - O(h) where h is height

TREE-SEARCH(x, k):
    if x == NIL or k == x.key:
        return x
    if k < x.key:
        return TREE-SEARCH(x.left, k)
    else:
        return TREE-SEARCH(x.right, k)

TREE-MINIMUM(x) and TREE-MAXIMUM(x) - O(h)

TREE-MINIMUM(x):
    while x.left ≠ NIL:
        x = x.left
    return x

TREE-MAXIMUM(x):
    while x.right ≠ NIL:
        x = x.right
    return x

INORDER-TREE-WALK(x) - O(n)

Prints keys in sorted order

INORDER-TREE-WALK(x):
    if x ≠ NIL:
        INORDER-TREE-WALK(x.left)
        print x.key
        INORDER-TREE-WALK(x.right)

TREE-INSERT(T, z) - O(h)

TREE-INSERT(T, z):
    y = NIL
    x = T.root
    while x ≠ NIL:
        y = x
        if z.key < x.key:
            x = x.left
        else:
            x = x.right
    z.p = y
    if y == NIL:
        T.root = z  // tree was empty
    else if z.key < y.key:
        y.left = z
    else:
        y.right = z

✓ Performance Characteristics

  • Best case (balanced tree): O(log n) operations
  • Worst case (skewed tree): O(n) operations
  • Average case (random insertions): O(log n)
  • Height h determines performance: h = O(log n) for balanced, h = O(n) for skewed

📖 BST Theory (Book Ch. 12)

Inorder Tree Walk: Printing all keys in sorted order takes Θ(n) time.

INORDER-TREE-WALK(x):
    if x ≠ NIL:
        INORDER-TREE-WALK(x.left)
        print x.key
        INORDER-TREE-WALK(x.right)

Why it works: BST property ensures left subtree ≤ root ≤ right subtree

Randomly Built BST: If you insert n random keys into an initially empty BST, the expected height is O(log n) even without balancing! (Problem 12-3 in book)

Connection to Quicksort: Comparisons to insert n elements into BST are same as comparisons in randomized quicksort (Problem 12-3f)

Successor and Predecessor

Successor of Node x

The successor of x is the node with the smallest key greater than x.key (next node in inorder walk)

TREE-SUCCESSOR(x) - O(h)

TREE-SUCCESSOR(x):
    if x.right ≠ NIL:
        return TREE-MINIMUM(x.right)  // Case 1
    else:
        // Case 2: Find lowest ancestor whose left child is ancestor of x
        y = x.p
        while y ≠ NIL and x == y.right:
            x = y
            y = y.p
        return y

Two Cases for Successor

Successor of 7 is 13 (Case 1: minimum in right subtree)

Understanding Successor

  • Case 1: If x has right subtree, successor is leftmost node in right subtree
  • Case 2: If no right subtree, go up until you find an ancestor you came from as a left child
  • Predecessor is symmetric: right-most in left subtree, or go up from right child
  • Both run in O(h) time

⚠️ Common Pitfalls & Worst Cases

Skewed Tree Problem

Inserting sorted data creates a skewed tree (essentially a linked list)!

Inserting 1,2,3,4,5,6,7 in order creates O(n) height!

Solution: Balanced BSTs

  • Red-Black Trees: Self-balancing, guarantee h = O(log n)
  • AVL Trees: Strictly balanced, h ≤ 1.44 log n
  • Randomization: Random insertion order gives expected O(log n)

🔍 Lecture 7: Breadth-First Search & Graph Distances

Breadth-First Search (BFS)

BFS explores vertices in order of their distance from the source.

BFS(G, s) - O(V + E)

BFS(G, s):
    for each vertex u in G.V - {s}:
        u.color = WHITE
        u.d = ∞
        u.π = NIL
    s.color = GRAY
    s.d = 0
    s.π = NIL
    Q = ∅
    ENQUEUE(Q, s)
    while Q ≠ ∅:
        u = DEQUEUE(Q)
        for each v in G.Adj[u]:
            if v.color == WHITE:
                v.color = GRAY
                v.d = u.d + 1
                v.π = u
                ENQUEUE(Q, v)
        u.color = BLACK

BFS Tree Example

BFS explores vertices layer by layer based on distance from source s

✓ BFS Properties

  • Finds shortest paths in unweighted graphs
  • v.d = shortest path distance from s to v
  • v.π forms a breadth-first tree
  • Time: O(V + E), Space: O(V) for queue
  • Uses FIFO queue (First In, First Out)

📖 BFS Correctness (Book Ch. 20.2)

Color Scheme:

  • WHITE: Undiscovered vertex
  • GRAY: Discovered but not fully explored (in queue)
  • BLACK: Fully explored (removed from queue)

Queue Property: If u is before v in queue, then u.d ≤ v.d. Queue contains at most 2 consecutive distance levels.

Shortest-Path Tree: For any reachable vertex v, the simple path from s to v in the breadth-first tree corresponds to a shortest path from s to v in G (minimum number of edges).

Graph Representations

1. Adjacency List - O(V + E) space

For each vertex u, store a list of adjacent vertices

Best for: Sparse graphs (E ≪ V²)

2. Adjacency Matrix - O(V²) space

Store a V×V matrix where entry (i,j) = 1 if edge exists

Best for: Dense graphs, quick edge existence checks

🎯 Applications of BFS

Where BFS is Used

  • Social Networks: Find people within N degrees of separation
  • Web Crawlers: Explore web pages level by level
  • GPS Systems: Find shortest route (with equal edge weights)
  • Peer-to-Peer Networks: Broadcasting messages
  • Garbage Collection: Find reachable objects
  • Maze Solving: Find shortest path to exit

🕳️ Lecture 8: Depth-First Search

Depth-First Search (DFS)

DFS explores as far as possible along each branch before backtracking.

DFS(G) - O(V + E)

DFS(G):
    for each vertex u in G.V:
        u.color = WHITE
        u.π = NIL
    time = 0
    for each vertex u in G.V:
        if u.color == WHITE:
            DFS-VISIT(G, u)

DFS-VISIT(G, u):
    time = time + 1
    u.d = time  // discovery time
    u.color = GRAY
    for each v in G.Adj[u]:
        if v.color == WHITE:
            v.π = u
            DFS-VISIT(G, v)
    u.color = BLACK
    time = time + 1
    u.f = time  // finishing time

DFS with Discovery/Finish Times

Numbers show discovery/finish times (d/f)

✓ DFS Properties

  • Uses LIFO stack (Last In, First Out) - implemented via recursion
  • Produces a depth-first forest (collection of DFS trees)
  • Parenthesis theorem: Intervals [u.d, u.f] are either nested or disjoint
  • Time: O(V + E), Space: O(V) for recursion stack

📖 Edge Classification in DFS (Book Ch. 20.3)

Four Types of Edges

  • Tree edges: Edges in the DFS forest Gπ. Edge (u,v) is a tree edge if v was first discovered by exploring (u,v). (v is WHITE when explored)
  • Back edges: Edges (u,v) connecting vertex u to an ancestor v in a depth-first tree (including self-loops). (v is GRAY when explored)
  • Forward edges: Non-tree edges (u,v) connecting vertex u to a proper descendant v in the depth-first tree. (v is BLACK, u.d < v.d)
  • Cross edges: All other edges - between vertices in same DFS tree (neither is ancestor) or between different DFS trees. (v is BLACK, u.d > v.d)

Lemma 20.11: Cycle Detection

A directed graph G is acyclic (DAG) if and only if DFS finds no back edges.

Proof: If there's a back edge (u,v), then v is ancestor of u, so path v → u exists. Adding (u,v) creates cycle. Conversely, any cycle contains a back edge when explored by DFS.

Edge Detection During DFS

When exploring edge (u, v):

  • v.color == WHITE: Tree edge (first time visiting v)
  • v.color == GRAY: Back edge (v is ancestor, still being processed)
  • v.color == BLACK: Forward or cross edge (v already finished)
    • If u.d < v.d: Forward edge (u is ancestor of v)
    • If u.d > v.d: Cross edge (neither is ancestor)

🌲 Lecture 8: Minimum Spanning Trees

Minimum Spanning Tree Problem

Given a connected, undirected graph G = (V, E) with edge weights w, find an acyclic subset T ⊆ E that connects all vertices and minimizes total weight.

MST Properties

  • A spanning tree T always has |V| - 1 edges
  • Adding any edge to T creates exactly one cycle
  • Removing any edge from T disconnects the graph

MST (green) with total weight = 14

📖 Generic MST Algorithm & Cut Property (Book Ch. 21.1)

Generic MST Method

All MST algorithms follow this pattern:

GENERIC-MST(G, w):
    A = ∅
    while A does not form spanning tree:
        find safe edge (u, v) for A
        A = A ∪ {(u, v)}
    return A

Loop Invariant: Prior to each iteration, A is a subset of some minimum spanning tree.

Key Definitions

  • Cut (S, V-S): Partition of V into two disjoint sets
  • Edge crosses cut: One endpoint in S, other in V-S
  • Cut respects A: No edge in A crosses the cut
  • Light edge: Edge crossing cut with minimum weight
  • Safe edge: Edge that can be added to A while maintaining invariant

Theorem 21.1: Recognizing Safe Edges

Let A ⊆ E be subset of some MST. Let (S, V-S) be any cut that respects A. Let (u, v) be a light edge crossing the cut. Then (u, v) is safe for A.

Proof idea: If MST T contains A but not (u, v), we can replace another edge crossing the cut with (u, v) without increasing total weight, creating another MST.

Corollary 21.2: Safe Edges for Components

If C is a connected component in forest GA = (V, A), and (u, v) is a light edge connecting C to another component, then (u, v) is safe for A.

This corollary is what Kruskal's and Prim's algorithms use!

How Algorithms Use This Theory

  • Kruskal: A is a forest. Safe edge = minimum-weight edge connecting two different components
  • Prim: A forms a single tree. Safe edge = minimum-weight edge connecting tree to a non-tree vertex

Kruskal's Algorithm

Build MST by greedily adding cheapest edges that don't create cycles

KRUSKAL(G, w) - O(E log E)

KRUSKAL(G, w):
    T = ∅
    for each vertex v in G.V:
        MAKE-SET(v)  // union-find
    sort edges of G.E by weight w
    for each edge (u, v) in sorted order:
        if FIND-SET(u) ≠ FIND-SET(v):
            T = T ∪ {(u, v)}
            UNION(u, v)
    return T

Kruskal's Strategy

  • Sort edges by weight: O(E log E)
  • Use union-find data structure to detect cycles
  • Process edges in order of increasing weight
  • Add edge if it doesn't create a cycle

Prim's Algorithm

Grow MST from a single vertex, always adding the cheapest edge connecting tree to non-tree vertex

PRIM(G, w, r) - O(E log V) with min-heap

PRIM(G, w, r):
    for each u in G.V:
        u.key = ∞
        u.π = NIL
    r.key = 0
    Q = G.V  // min-priority queue
    while Q ≠ ∅:
        u = EXTRACT-MIN(Q)
        for each v in G.Adj[u]:
            if v ∈ Q and w(u,v) < v.key:
                v.π = u
                v.key = w(u,v)  // DECREASE-KEY

Prim's Strategy

  • Start from arbitrary root vertex r
  • Maintain set of vertices already in MST
  • Use priority queue to find minimum-weight crossing edge
  • v.key = minimum edge weight connecting v to MST
  • With Fibonacci heap: O(E + V log V)

🛣️ Lecture 9: Dijkstra's Algorithm

Single-Source Shortest Paths

Problem: Given directed graph G = (V, E) with non-negative edge weights and source s, find shortest path from s to every vertex.

Dijkstra's Greedy Choice

Always choose the vertex v with minimum distance estimate among unexplored vertices

Score: dscore(v, w) = len(v) + l(v,w)

DIJKSTRA(G, w, s) - O((V + E) log V)

DIJKSTRA(G, w, s):
    // Initialization
    for each vertex v in G.V:
        v.d = ∞
        v.π = NIL
    s.d = 0
    S = ∅  // explored set
    Q = G.V  // min-priority queue
    
    // Main loop
    while Q ≠ ∅:
        u = EXTRACT-MIN(Q)  // minimum d value
        S = S ∪ {u}
        for each vertex v in G.Adj[u]:
            // Relaxation
            if v.d > u.d + w(u, v):
                v.d = u.d + w(u, v)
                v.π = u
                DECREASE-KEY(Q, v)

Dijkstra's Algorithm Example

Shortest path from s to x = 5 (shown in red)

✓ Dijkstra's Properties

  • Requirement: All edge weights must be non-negative
  • Greedy algorithm: Makes locally optimal choice
  • Once a vertex is explored, its distance is final
  • With binary min-heap: O((V + E) log V)
  • With Fibonacci heap: O(E + V log V)
  • Can reconstruct paths using π pointers

📖 Shortest Paths Theory (Book Ch. 22)

Lemma 22.1 - Optimal Substructure: Subpaths of shortest paths are shortest paths.

If p = ⟨v₁, v₂, ..., vₖ⟩ is shortest path from v₁ to vₖ, then any subpath pij from vᵢ to vⱼ is also shortest.

This is why dynamic programming and greedy methods work for shortest paths!

Shortest Paths Are Simple: Any shortest path contains at most |V| - 1 edges (no cycles).

  • Can't contain negative-weight cycles (undefined)
  • Can't contain positive-weight cycles (removing cycle improves weight)
  • Can remove any 0-weight cycles without changing total weight

Relaxation: Core technique of all shortest-path algorithms

RELAX(u, v, w):
    if v.d > u.d + w(u,v):
        v.d = u.d + w(u,v)  // improve estimate
        v.π = u              // update predecessor

Tests if going through u improves path to v. Dijkstra relaxes each edge exactly once!

Shortest-Path Tree: π pointers form a rooted tree containing shortest paths from s to all reachable vertices.

⚠️ Why Negative Weights Fail

Critical Limitation: NO Negative Edge Weights!

Dijkstra's algorithm assumes once a vertex is explored (added to X), its shortest path distance is final. Negative weights violate this assumption.

Counterexample with Negative Weights

Dijkstra chooses s→t→w (cost -2 + ?) but the true shortest is s→v→w (cost 1 + (-5) = -4). Once t is finalized at -2, Dijkstra never reconsiders it!

Why Adding Constants Doesn't Work

Can't just add +C to all edges! Different paths have different numbers of edges:

  • Path 1: 2 edges, original cost = -4, +5 each = -4 + 10 = 6
  • Path 2: 1 edge, original cost = -2, +5 each = -2 + 5 = 3
  • Still picks wrong path! ✗

Solution: Use Bellman-Ford algorithm for negative weights (not covered here)

Heap-Based Dijkstra Optimization

Invariant with Heap

For each vertex w ∈ (V - X): key(w) = minimum Dijkstra score among all edges from X to w (or +∞)

key(w) = minv∈X, (v,w)∈E (len(v) + lvw)

Dijkstra with Min-Heap - O((V + E) log V)

DIJKSTRA-HEAP(G, w, s):
    X = ∅  // explored vertices
    H = empty min-heap
    key[s] = 0
    for each v ≠ s:
        key[v] = +∞
    INSERT-ALL(H, V)  // Heapify: O(V)
    
    while H ≠ ∅:
        w = EXTRACT-MIN(H)  // O(log V)
        X = X ∪ {w}
        len(w) = key[w]
        
        // Update keys for w's neighbors
        for each edge (w, z) with z ∉ X:
            if key[z] > len(w) + lwz:
                key[z] = len(w) + lwz
                DECREASE-KEY(H, z)  // O(log V)

Complexity Analysis

  • Initialization: O(V) for heapify
  • EXTRACT-MIN: Called V times → V × O(log V) = O(V log V)
  • DECREASE-KEY: At most once per edge → E × O(log V) = O(E log V)
  • Total: O((V + E) log V)

Relaxation

Edge Relaxation

For edge (u, v) with weight w(u, v):

RELAX(u, v, w):
    if v.d > u.d + w(u, v):
        v.d = u.d + w(u, v)
        v.π = u

Update v's distance if path through u is shorter

Key idea: "Can we improve the path to v by going through u?"

🎯 Applications of Dijkstra

Real-World Uses

  • GPS Navigation: Finding shortest routes (distance or time)
  • Network Routing: OSPF protocol uses Dijkstra
  • Robot Path Planning: Navigating through obstacles
  • Social Networks: Degrees of separation
  • Game AI: Pathfinding for NPCs

📊 Lecture 9: Topological Sort

Topological Ordering

A topological order of a directed graph G = (V, E) is a linear ordering of vertices such that for every edge (u, v), u appears before v.

Existence Theorem

A directed graph has a topological ordering if and only if it is a DAG (Directed Acyclic Graph).

Example: Course Prerequisites

One valid ordering: Intro CS → Algorithms → AI → Data Str. → ML → Thesis

Topological Sort Algorithm

TOPOLOGICAL-SORT(G) - O(V + E)

TOPOLOGICAL-SORT(G):
    call DFS(G) to compute finishing times v.f
    as each vertex is finished, insert it to front of list
    return the linked list of vertices

Alternative: Using DFS Recursively

DFS-TOPO(G):
    mark all vertices as unvisited
    curLabel = n  // assign labels in reverse order
    for each vertex v in G.V:
        if v is unvisited:
            DFS-VISIT-TOPO(v)

DFS-VISIT-TOPO(v):
    mark v as visited
    for each edge (v, w):
        if w is unvisited:
            DFS-VISIT-TOPO(w)
    f(v) = curLabel  // assign label after exploring
    curLabel = curLabel - 1

✓ Key Insight

  • Process vertices in decreasing order of finishing time
  • If there's an edge (u, v), then u.f > v.f (u finishes after v)
  • Reversing the finish order gives topological sort
  • Can detect cycles: if back edge found, graph is not a DAG

⭐ Lecture 10: A* Search Algorithm

A* Heuristic Search

A* improves on Dijkstra by using a heuristic function to guide the search toward the goal.

A* Score Function

f(v) = g(v) + h(v)

  • g(v): Actual cost from start to v (like Dijkstra)
  • h(v): Heuristic estimate of cost from v to goal
  • f(v): Estimated total cost of path through v

A*(G, s, t, h) - Finds shortest path from s to t

A*(G, s, t, h):
    for each vertex v in G.V:
        v.g = ∞
        v.f = ∞
    s.g = 0
    s.f = h(s)
    openSet = {s}  // priority queue by f value
    
    while openSet ≠ ∅:
        current = vertex in openSet with lowest f value
        if current == t:
            return reconstruct_path(t)
        
        remove current from openSet
        for each neighbor v of current:
            tentative_g = current.g + weight(current, v)
            if tentative_g < v.g:
                v.g = tentative_g
                v.f = v.g + h(v)
                v.parent = current
                if v not in openSet:
                    add v to openSet
    
    return failure  // no path exists

✓ Admissible Heuristic

For A* to be optimal, h(v) must be admissible:

  • h(v) ≤ actual cost from v to goal (never overestimates)
  • h(goal) = 0
  • Example: Straight-line distance for map navigation

A* vs Dijkstra Exploration

A* explores fewer nodes by using heuristic guidance

A* Optimality

If h is admissible and consistent (h(u) ≤ cost(u,v) + h(v)), then A* is optimal and complete.

💡 Lecture 11: Dynamic Programming

Dynamic Programming Fundamentals

Dynamic Programming solves optimization problems by breaking them into overlapping subproblems.

When to Use DP

  • Optimal substructure: Optimal solution contains optimal solutions to subproblems
  • Overlapping subproblems: Same subproblems solved multiple times

DP Approaches

  • Top-down (Memoization): Recursive with caching
  • Bottom-up (Tabulation): Iterative, fill table

Example: Rod Cutting Problem

Problem: Given a rod of length n and prices p[i] for rods of length i, find maximum revenue by cutting the rod.

Bottom-Up Rod Cutting - O(n²)

BOTTOM-UP-CUT-ROD(p, n):
    let r[0..n] be a new array
    r[0] = 0
    for j = 1 to n:
        q = -∞
        for i = 1 to j:
            q = max(q, p[i] + r[j-i])
        r[j] = q
    return r[n]

Rod Cutting Example (n=4)

Optimal: Cut into two pieces of length 2 each (revenue = 10)

⚠️ Why Naive Recursion is Exponential

Exponential Time Without Memoization!

Naive recursive CUT-ROD: T(n) = 2n-1

For n=30: ~536 million recursive calls! With DP: only ~900 operations

Time-Memory Trade-off

  • Naive recursion: O(2n) time, O(n) space (call stack)
  • Memoized (top-down DP): O(n²) time, O(n) space
  • Bottom-up DP: O(n²) time, O(n) space
  • Key insight: Store subproblem solutions, don't recompute!

Longest Common Subsequence (LCS)

Problem Statement

Find longest subsequence common to two sequences (not necessarily contiguous)

Example: X="ABCBDAB", Y="BDCAB" → LCS="BDAB" (length 4)

LCS-LENGTH(X, Y) - O(mn)

LCS-LENGTH(X, Y):
    m = length(X)
    n = length(Y)
    let c[0..m, 0..n] be a new table
    for i = 0 to m:
        c[i, 0] = 0
    for j = 0 to n:
        c[0, j] = 0
    for i = 1 to m:
        for j = 1 to n:
            if X[i] == Y[j]:
                c[i, j] = c[i-1, j-1] + 1  // match!
            else:
                c[i, j] = max(c[i-1, j], c[i, j-1])
    return c[m, n]

Recurrence Relation

c[i, j] = {

  • 0 if i=0 or j=0
  • c[i-1, j-1] + 1 if xi = yj
  • max(c[i-1, j], c[i, j-1]) otherwise

}

🎯 LCS Applications

  • Diff/Patch Tools: Compare file versions (Git, SVN)
  • Bioinformatics: DNA/protein sequence alignment
  • Plagiarism Detection: Compare text documents
  • Spell Checkers: Find similar words

0-1 Knapsack Problem

Problem Statement

Given items with weights w[i] and values v[i], and knapsack capacity W, maximize value without exceeding capacity.

Constraint: Each item can be taken 0 or 1 times (not fractional)

Recurrence Relation

K[i, w] = maximum value using items 1..i with capacity w

K[i, w] = {

  • 0 if i=0 or w=0
  • K[i-1, w] if w[i] > w (item too heavy)
  • max(K[i-1, w], v[i] + K[i-1, w-w[i]]) otherwise

}

Choice: Exclude item i OR include it (if it fits)

Knapsack Example

Optimal: Take items 1 and 2 (total value $7 with 5kg capacity)

Complexity: O(nW)

Note: This is pseudo-polynomial! W is not polynomial in input size (number of bits needed to represent W)

If W is exponentially large, this becomes exponential time

🎯 DP Problem-Solving Framework

4-Step Approach

  1. Characterize structure: Define optimal solution in terms of subproblems
  2. Define recurrence: Write recursive formula relating problem to subproblems
  3. Compute bottom-up or memoize: Fill table or cache results
  4. Construct solution: Backtrack through table to find actual solution (not just value)

Common DP Patterns & Examples

Pattern Space Examples
1D Linear O(n) Fibonacci, Climbing Stairs, House Robber
2D Grid O(mn) LCS, Edit Distance, Knapsack, Grid Path
Interval DP O(n²) Matrix Chain, Palindrome Partition
State Machine Varies Stock Trading, State-based Problems
Bitmask DP O(2n) TSP, Subset Sum with states

When to Use DP?

  • Optimal Substructure: Optimal solution contains optimal solutions to subproblems
  • Overlapping Subproblems: Recursive algorithm revisits same problems many times
  • Tip: If naive recursion is exponential due to overlap, DP can likely help!
